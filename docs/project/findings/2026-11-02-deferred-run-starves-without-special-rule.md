# 2026-11-02: a run with one long step starves unless someone writes it a special rule
**What happened:** Darwin's v5 audience relabel dry run (run 17918, one 120 s `audience-relabel` step), queued Nov 1 22:50 UTC so its count could go to James, had not started by Nov 2 02:35. It deferred 9 times in 3 hours: "needs about 120 s and the tick has 35-97 s left".
**Cause:** `executeQueuedAgentRuns` promotes long single-step runs only by name: the scoreboard, the live-source audit (#2061, 929 deferrals in 12 days) and the one-off paid batches (#2851) each got their own `ORDER BY` term after they starved. Any run not on those lists is reached after lanes and runs under way have used the tick, so a step longer than what is left never runs.
**Fix:** one general aging term: a run that is not a lane or a report, queued 30+ minutes, whose next step deferred `DEFERRAL_AGING_MIN_DEFERRALS` (3) times in the last 2 hours, ranks ahead of state lanes. Paying provider and marketing steps are never promoted this way, so paid work and outreach keep their gates.
**Lesson:** Fix starvation once, by how long a run has been deferred, not by naming each run that starved; a new long step should never need its own tick-order rule.
**Guard:** `src/lib/agents/run-store.test.ts` ("ranks a run whose next step keeps deferring ahead of lanes, never a provider or marketing step").
