# 2026-10-18: Hamilton server actions skip the /pro gate
**What happened:** the #1920 billing-access journey (go-live gate G10) signed in as one synthetic account per billing state and called every Hamilton page, API route and read server action over HTTP against a local production build. Every page and API route gave each state what `canAccessPremium` and `isPaymentLapsed` say it should. Six server actions did not: a free, cancelled, expired, lapsed past-due or lapsed-seat account got its own saved Hamilton answers and scenarios back. The actions were `listSavedAnalyses`, `loadAnalysisRecord` and `loadAnalysis` (Analyze), `loadActiveScenarios` and `loadScenarioById` (Reports), and `getIntelligenceSnapshot` (Settings). A signed-out visitor was still refused (src/proxy.ts sends `/pro` to `/login`), and no account could read another account's rows.
**Cause:** a server action is called by POSTing its id to any page, and it runs without that page's layouts. The `/pro` layouts hold the subscription check, so each action must repeat it. These six checked only for a session. Their sibling reads (`loadReport`, `listScenarios`) already checked `canAccessPremium`.
**Fix:** the same PR adds `canAccessPremium` to those six, plus `getScenario` and `loadRecentReports` (same pattern, not callable from the browser today). `tests/e2e/hamilton/billing-access.test.ts` (CI unit job) now fails if any exported server action under `src/app/pro` lacks its own access check, or if an action, page or route handler under the Hamilton folders is left out of `billing-access.ts`. The same PR corrects three `authRequirement` labels in `src/lib/api-hardening/policies.ts` that did not match the route's real check. They are audit labels only: `/api/reports/peer-brief/confirm` (premium, not public), `/api/reports/generate` (cron or admin, not session) and `/api/reports/catalog` (public, not session).
**Lesson:** a layout gate never covers a server action. Every `"use server"` export checks access in its own body.

Run the journey locally (steps in `2026-10-17-hamilton-release-runbook.md`; no browser is launched):
`E2E_DATABASE_URL=... npx playwright test -c tests/e2e/hamilton/playwright.config.ts billing-access`. The observed matrix is written to `test-results/hamilton-billing-access/matrix.md`.
