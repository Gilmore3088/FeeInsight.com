# 2026-11-08: Financial routing and contract revision authority

**What happened:** Independent source audits found regulator financial parsing, public-data read doors, report calculations and paid/export authority that defaulted to R1 or omitted their owning specialists. Independent literal cases failed against the unchanged classifier before the fix. A supplemental audit found FFIEC overdraft revenue, NCUA call-series lineage and the national quarterly report still outside a finite exception table. The preparation audit also exposed Git attributes and npm shrinkwrap as executable controls still classified R1; independent cases failed for their risk and policy-sensitive labels before correction.

**Cause:** Risk and skill paths covered agent directories but missed shared financial code and inline access owners. The execution system also encoded only two numeric pilot selectors, conflating a root-cause issue with one frozen contract revision. Adding a JSON file alone could not create a supported successor or preserve the meaning of old native receipts.

**Fix:** The proposed Foundation #1048 change routes source-reviewed financial/access owners, including documented data-catalog and report-assembler code families, with R3 precedence and inert/nonfinancial controls. Independent fixture expectations remain in the trusted parent; the isolated source adapter returns only actual classifier values. A finite registry propagates the explicit successor key through preparation, runner, workflow, artifact, event, collector and scorecard. Unknown/ambiguous selection and nonregular/escaping contract files block. The two original contract files stay byte-for-byte unchanged. Changed shared execution makes their genuine native behavioral proofs historical-only for current decisions; all original run, attempt, artifact, hash and retention checks remain required. Independent review required two additional safeguards before publication: final native PR reads reparse the selected marker even when the head is unchanged, and historical workflow bytes match a separately pinned reviewed digest. Further review found that the workflow first executes a preparation CLI: freezing the runner alone leaves that earlier import and dependency chain able to rewrite the workspace. The successor therefore freezes the full preparer/import/toolchain closure and rejects extra npm configuration or module-resolution inputs. Legacy history is restricted to exact reviewed native source commits, binding its whole source tree without changing the original JSON. Canonical Git tree modes protect execution inputs as well as declarations. Registered workflow identity or successful receipt assertions alone cannot prove the frozen runner executed.

**Lesson:** A file's real financial or access responsibility determines its routing. A new accepted version needs its own immutable proof and review bindings; neither a registry label nor authentic old history authorizes current code.

**Guard:** `src/lib/engineering-verification/financial-routing.test.ts`, `contract-registry.test.ts`, `policy-v2-pilot.test.ts` and the CLI/runner/native collector/event/scorecard/workflow boundary tests. Foundation #1048 retains exact-head protected owner authorization and trusted post-bootstrap proof as pending.

The proposal changes no GitHub permission/protection/enforcement setting, invokes no provider and writes no production data. Current-only interface tests and missing-module setup failures are not historical RED. Browser action/effect acceptance, machine-reviewer provenance, private holdouts and live production observations remain separate work.
