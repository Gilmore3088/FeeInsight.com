# 2026-11-08: Measurement execution could stand in for repaired work

**What happened:** An independent acceptance audit reproduced a false production-verification result. With an exact deployment, sufficient passing Deming samples and completed measurement rows, the assessor could return `PRODUCTION_VERIFIED` even though the repaired Knox step had never executed. The independent regression failed against the committed reader before implementation; its local RED receipt remains separate from production evidence.

**Cause:** The runtime reader constructed Atlas execution rows from Deming/Bayes measurement events, and the assessor accepted any completed row with matching deployment identity. Neither required the changed owning step, actual affected units nor their processed-output lineage. A quality window could also precede the repair's actual execution.

**Fix:** Foundation #1048 adds a conservative read-only owning-execution witness in this proposal. A frozen policy names the owning agent/step and every affected institution/document pair. The first supported output adapter is Knox extraction: native same-step extraction attempts, server execution and completion must corroborate positive inserted output for every selected pair with precise ordering and deployment identity. Input parameters, aggregate counts and capped samples cannot substitute for full selected-unit lineage. Unsupported roles, ambiguous ordering and insufficient output remain unverified. The bounded native inventory includes later failed work without attempt rows; institution intent cannot hide free extraction's global tails. Eligible measurements and replay checks must start after all work/recovery completes. Native database measurement timestamps govern duration/cadence; worker timestamps remain diagnostic. Existing thresholds and cadence limits are preserved.

**Lesson:** A measurement run proves the measurement ran. An operational repair claim separately needs the actual owning work and attributable outcomes after it completed. Code verification never authorizes a live rerun, provider spend or a production-data change.

**Guard:** `src/lib/engineering-verification/runtime.test.ts`, `src/lib/engineering-verification/evidence.test.ts`; Foundation #1048 retains actual deployed execution and outcome acceptance as open work.

Independent review also preserved actual free-extraction outputs where inserted rows exceed candidate yield, including a rate-only `no_candidates` result with positive inserted output. Pre-repair bad-quality samples cannot invalidate a later complete eligible outcome window. Tests retain the original behavioral failures and the real SQL counterexamples separately from final passing execution; no local fixture is production acceptance.
